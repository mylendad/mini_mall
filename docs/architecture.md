# Архитектура платформы

Платформа построена как **монорепозиторий автономных микросервисов** с
единственной общей библиотекой строго инфраструктурного назначения.

## Принципы

1. **Автономность сервисов.** Каждый сервис имеет собственную папку
   (`services/<name>/`) со своим `pyproject.toml`, `Dockerfile`, базой данных,
   миграциями и тестами. Условно «сервис один в мире»: внутри контейнера ему не
   известны пути других сервисов.
2. **Изоляция данных.** Одна БД на сервис (database-per-service). Сервисы не
   делают кросс-запросы к чужим базам.
3. **Строгая граница общего кода.** `libs/common` содержит **только
   инфраструктуру**: конфигурацию, логирование, middleware трассировки,
   Prometheus-метрики, стандартный формат ошибок, конверт событий. Доменная
   логика туда не кладётся.
4. **Локальная линковка пакетов.** Общая библиотека публикуется как пакет
   `common` и подключается к сервисам локальной зависимостью — без публикации
   приватных пакетов в PyPI. Это сохраняет независимость сервисов и не
   усложняет жизнь.
5. **Единый импортный лейаут `app.*`.** Код сервиса импортируется как
   `from app.config import ...`, `from app.database import ...`. Это исключает
   дублирование модулей (проблему «`database` vs `app.database`»), когда один и
   тот же код загружается дважды с разными путями.

## Структура репозитория

```text
mini_mall_2/
├── gateway/                # API-шлюз (входная точка платформы)
├── libs/
│   └── common/             # пакет common (см. libs-common.md)
│       ├── pyproject.toml  # контракт пакета (имя, версия, зависимости)
│       └── common/         # сам код: config, errors, events, logging,
│                           #   middleware, observability
├── services/
│   ├── auth/               # сервис аутентификации (см. services/auth.md)
│   │   ├── pyproject.toml
│   │   ├── Dockerfile
│   │   ├── alembic/        # миграции БД
│   │   ├── app/            # код сервиса: пакет app.*
│   │   └── tests/          # unit + интеграционные тесты
│   └── template/           # шаблон нового сервиса
├── infrastructure/         # docker-compose (postgres/redis/kafka/...)
├── tests/                  # сквозные тесты платформы
├── openspec/               # спецификации (foundation, auth-service)
└── docs/                   # эту документацию
```

## Микросервис глазами самого себя

Внутри контейнера (или локального окружения) сервис работает так, будто он
изолирован:

```text
/                   # корень контейнера
└── .../site-packages/
    ├── app/       # пакет сервиса (устанавливается из services/<name>/app)
    ├── common/    # общая библиотека (собирается из libs/common)
    └── fastapi, sqlalchemy, ...  # обычные зависимости из PyPI
```

Запуск — из рабочего каталога сервиса, максимально коротким путём:

```bash
uvicorn app.main:app
```

Никаких `PYTHONPATH=…` и длинных путей вроде `services.auth.app.main:app`.

## Как линкуется `common`

### Для локальной разработки

1. Пакет `common` устанавливается в виртуальное окружение editable-режимом:

   ```bash
   .venv/bin/pip install -e libs/common
   ```

   (либо, если используется uv: `uv sync`/`uv pip install -e libs/common`).

2. В `pyproject.toml` сервиса объявлена зависимость `common >= 0.1.0`, а
   локальный путь — через секцию uv-источников:

   ```toml
   [project]
   dependencies = ["common>=0.1.0", ...]

   [tool.uv.sources]
   common = { path = "../../libs/common", editable = true }
   ```

### Для Docker-сборки

Сборка запускается **из корня репозитория**, поэтому внутри образа сначала
собирается `common` (через `pip wheel libs/common`), затем сервис. В итоговом
образе оба пакета установлены как обычные библиотеки. См.
[Контейнеризация](docker.md).

## Границы ответственности «кто куда»

| Код | Куда класть |
| --- | --- |
| Конфигурация конкретного сервиса | `services/<name>/app/config.py` |
| Базовый класс настроек | `libs/common/common/config.py` (`BaseAppSettings`) |
| Бизнес-логика сервиса | `services/<name>/app/**` |
| Логирование, middleware, метрики, формат ошибок, конверт событий | `libs/common/common/**` |
| Общая доменная логика между сервисами | не допускается — выносится в сервис или отдельный сервис |
| Сквозные тесты платформы | корневые `tests/` |
| Спецификации и ADR | `openspec/` |

## Версии Python и инструменты

- Все модули: **Python >= 3.12**.
- Пакетный менеджер: pip (базовый поток) или uv (рекомендуется для работы с
  `[tool.uv.sources]`).
- Линт: `ruff`; тесты: `pytest` + `pytest-asyncio` (session-scope) +
  Testcontainers.
- Миграции: Alembic (async-движок SQLAlchemy).
